# Бенчмаркинг сервиса рельефа

Замер времени и точности `sima-relief-service`: локально — на датасете триплетов
`test_data/dsm_dataset` (ОФП + ВЛС + эталонная ЦМР), по сети — на материалах из
бакета `geomate-project`.

## Состав

| Файл | Назначение |
|---|---|
| `relief_bench.py` | харнесс локального прогона: отбор триплетов, конвейер, замеры, метрики точности, покрытие листа облаком (`las_coverage`) |
| `s3_relief.py` | харнесс прогона из S3: каталог бакета, загрузка, конвейер, замеры, карты тайлов; датасеты описаны в `DATASETS` |
| `results/` | локальный прогон: `results.jsonl`, `las_coverage.csv`, CSV-сводки из ноутбука |
| `results_s3_yuilskiy/` | Юильский из S3: `results.jsonl` и `previews/*.png` |
| `results_s3_yuzhno_zimniy/` | Южно-Зимний из S3, там же |
| `results_s3_forest_yuilskiy/` | древостой на Юильском |
| `../relief_benchmark.ipynb` | локальный прогон: скорость, точность, полнота, карты каждого десятого листа |
| `../relief_s3_yuilskiy.ipynb`, `../relief_s3_yuzhno_zimniy.ipynb` | те же замеры на данных из бакета |

Прогон из S3 запускается и без ноутбука — тогда ноутбук только рисует готовое:

```bash
.venv/bin/python benchmarks/s3_relief.py --dataset yuilskiy --limit 100 --restore-z
.venv/bin/python benchmarks/s3_relief.py --dataset yuzhno_zimniy --limit 30
```

`--restore-z` восстанавливает абсолютные Z из ТЛО по эталонной ЦМР бакета: без
него на Юильском ЦМР вырождается в плоскость, а уклон, экспозиция, TPI и
горизонтали выходят пустыми.

## Воспроизведение

Полный прогон (123 триплета, ≈15 мин на 1 потоке):

```bash
cd backend
.venv/bin/python benchmarks/relief_bench.py \
    --root "/Users/sergeyzay/Documents/НЕДРА/СИМА/test_data/dsm_dataset" \
    --out benchmarks/results
```

Пробный прогон на нескольких тайлах с сохранением артефактов:

```bash
.venv/bin/python benchmarks/relief_bench.py --limit 3 --keep-outputs --out /tmp/bench
```

Затем анализ — `backend/relief_benchmark.ipynb` (ядро `sima-backend`;
регистрируется командой `.venv/bin/python -m ipykernel install --user
--name sima-backend --display-name "SIMA backend (.venv)"`). Ноутбук по умолчанию
читает готовый `results.jsonl`; чтобы перезапустить расчёт из ноутбука, установить
`RUN_BENCHMARK = True`.

## Что и по каким ячейкам считается

Точность считается **только по измеренным ячейкам** — тем, значение которых
получено растеризацией точек. Ячейки, достроенные заполнением пустот, описывают
качество интерполяции, а не построения рельефа; смешивать их в одном числе
значит мерить два разных свойства.

Маску измеренных ячеек снимает сам сервис (`ReliefService(save_measured_mask=True)`)
сразу после растеризации и до любого заполнения — по готовому растру отличить
измеренную ячейку от достроенной уже нельзя. Маска пишется рядом с ЦМР как
`<stem>_dem_measured.tif` и переносится на сетку эталона тем же bilinear-приведением,
что и сам растр, с порогом 1.0.

Метрики по всем ячейкам сохраняются рядом, в `accuracy.<слой>.all_cells`.

Разница на текущем прогоне (123 листа, ЦМР):

| | по измеренным | по всем |
|---|---|---|
| RMSE, медиана | 0.069 м | 0.116 м |
| RMSE, p95 | 0.087 м | 0.192 м |
| RMSE, max | 0.092 м | 0.359 м |
| доля площади листа | 16.2 % | 99.5 % |

## Заполнение пустот: одна настройка

`default_params(crs, resolution, fill_method)` — `fill_method` принимает
`"laplace"` (гармоническая интерполяция, гладкая, без лучей) или `"idw"`
(`GDALFillNodata`, поведение легаси). Заполняются **все** пустоты растра, включая
приграничные (`edge_extrapolation_m` заведомо больше листа), поэтому дыр в выдаче
не остаётся. Границу задаёт не алгоритм, а сам растр: `writers.gdal` строит его по
габариту облака, за пределы съёмки расчёт не выходит.

Сравнение методов на озёрных тайлах (RMSE в зоне, которая раньше оставалась
пустой): laplace 0.114 и 0.255 м, idw 0.128 и 0.299 м; максимум отклонения 0.86
против 1.15 м. Поэтому по умолчанию `laplace`.

**Гидровыравнивание выключено** (`hydro_flatten=False`). Механизм в библиотеке
исправен: кандидатом в водоём может быть только область без единого возврата ВЛС
(`GroundProcessing._no_return_mask` — растр `count` по тому же облаку, передаётся
в `fill_voids(water=...)`); раньше кандидатом считалась любая замкнутая пустота от
0.8 га, а у ЦМР валидная маска — редкая сетка ground-ячеек, поэтому «лакуной»
оказывался почти весь лист и выравнивался в одну плоскость с провалами до 8 м.
Но в демо-конфигурации он не нужен: эталонные ЦМР датасета воду тоже
интерполировали, и плоская отметка расходится с ними до 1.7 м (RMSE 0.074 → 0.190
на P-42-053-064-i). Выбор «плоскость против интерполяции» этим датасетом не
проверяется — он решается стандартом (3DEP требует плоскость) и брейклайнами.

Прогоны прошлых состояний сохранены рядом: `results/results_before_hydro_fix.jsonl`.

## Полнота растра и покрытие ЛАС

`las_coverage()` считает по самому облаку, на сетке эталона, до всякой
растеризации: какую долю листа накрывает габарит облака, в скольких ячейках есть
хотя бы одна точка и в скольких — ground-точка. Медианы по 123 листам:

| | % площади листа |
|---|---|
| габарит облака ВЛС | 100 |
| ячейки с точками ВЛС | 81 |
| ячейки с ground-точками | 18 |
| измеренные ячейки ЦМР | 16 |
| полнота растра ЦМР | 99.5 |

Растр выходит полным, поэтому полнота сама по себе ничего не характеризует —
значимы две другие величины. Первая: **измерено 16 % листа** — только эта часть
опирается на съёмку, остальное достроено интерполяцией между измерениями.
Вторая: **12 % листа (медиана; p95 — 29 %) достроено там, где возвратов ВЛС не
было вовсе** — внутренние провалы съёмки, где интерполяция уже не уточняет
измерения, а замещает их. Приёмочный критерий поэтому формулируется в двух
числах: RMSE по измеренным ячейкам и доля измеренных ячеек.

## Ограничение методологии

ВЛС датасета хранит **ТЛО** (`Z = HeightAboveGround`), а не абсолютные отметки.
Абсолютные Z восстанавливаются по эталонной ЦМР (`restore_absolute`), поэтому
сравнение с эталоном измеряет точность **реконструкции поверхности сервисом**
(SMRF → IDW → заполнение дыр), а не независимую точность съёмки. Подробнее —
в шапке ноутбука и docstring `relief_bench.py`.
